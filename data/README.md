# Data card

All bundled incident observations were generated by `tracelens.data`. There are no customer logs, proprietary traces, or external benchmark examples in this folder.

- `incidents.jsonl.gz`: 720 normalized public observations; no ground-truth fields.
- `labels.jsonl`: separate experimental labels for training/evaluation only.
- `demo-incidents.jsonl`: 16 fixed held-out observations exported for the API.
- `manifest.json`: seed, source, counts and partition policy.

Six service names and five generating fault families are used. Each base experiment has two observations. Both stay in the same split. IDs are opaque sequential identifiers and are excluded from features. The title is generic and conveys no cause. A recent deployment can be unrelated to the actual cause. Distractors and propagated symptoms are intentionally present.

This is purpose-built educational data. Its convenience and repeatability are not evidence of realism. Extremely high scores can reflect generator assumptions and repeated templates. Synthetic train/test separation does not substitute for an independent real-data evaluation.

## Public incident schema

`Incident` in `src/tracelens/schema.py` is the executable specification. A record has an ID, source, start time, aligned per-service metric series, logs, dependency/local spans and optional deployments. Numeric values must be finite; IDs and references are checked; arrays are bounded; additional fields such as `root_service`, `fault_family`, `split` and `experiment_id` are rejected.

The model expects error rate as a fraction, latency in milliseconds, CPU as a percentage, memory in MB, request rate per second and queue depth as a count. Use at least eight aligned samples with an early baseline. The feature extractor resamples to 24 steps. Do not feed milliseconds as seconds, cumulative counters as rates, or CPU cores as percentages.

## External data

No RCAEval data was downloaded or benchmarked during project creation. Consult its upstream repository and dataset license before downloading. It offers multiple layouts; a universal adapter is not included. Map your selected layout explicitly into this public schema and keep injection times/labels in a separate evaluation store.

The included OTLP adapter is a trace-file subset adapter, not an RCAEval loader. It derives observed error/latency/request counts from spans. Resource metrics are unavailable and filled as unknown zeros; these inputs must remain uncalibrated until a compatible model is trained.
